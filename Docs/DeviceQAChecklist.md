## Required Evidence Folder

For each IPA pass, create:

```text
build/device-qa/<YYYYMMDD-HHMMSS>/
```

Minimum evidence:

- `device-list.txt` from `xcrun devicectl list devices`.
- `xcdevice-list.json` from `xcrun xcdevice list`.
- `idevice-id-list.txt` from `idevice_id -l`. Use this UDID with
  `Scripts/collect-device-qa-logs.sh`; CoreDevice identifiers are not always
  accepted by `idevicesyslog`.
- `idevice-id-network-list.txt` from `idevice_id -n -l`, if testing over
  libimobiledevice network pairing.
- `motionreveal-device.log` captured during import, playback, and Live Activity
  checks.
- `import-events.log`, generated from the MotionReveal log, containing the
  import breadcrumb chain only.
- `idevicesyslog.stderr.log`, especially when no device is connected or the log
  stream fails.
- `manifest.txt`, generated by `Scripts/collect-device-qa-logs.sh`, containing
  the device-log paths plus the sideload manifest fields for the exact IPA under
  test.
- Photos or screen recordings for Dynamic Island and Files import failures.
- The exact IPA SHA-256 from `build/sideload/manifest.txt`.

The helper scripts are:

```sh
Scripts/package-sideload-ipa.sh
Scripts/collect-device-qa-logs.sh [DEVICE_UDID] [SECONDS]
```

## Crash And Log Capture

Before any risky device flow, run:

```sh
Scripts/collect-device-qa-logs.sh [DEVICE_UDID] 120
```

During the 120 seconds, reproduce the issue. Attach the generated
`motionreveal-device.log` and `device-list.txt` path to the issue note below.
If `idevicesyslog.stderr.log` says no device was found, connect the iPhone by
USB and check `idevice-id-list.txt`. Pass one of those libimobiledevice UDIDs
to the script; CoreDevice "available" alone is not enough for the current log
stream helper.
For network-paired devices, check `idevice-id-network-list.txt` and run:

```sh
MOTIONREVEAL_IDEVICE_NETWORK=1 Scripts/collect-device-qa-logs.sh [NETWORK_UDID] 120
```

For Files import failures, also attach `import-events.log`. A useful import
trace should show:

```text
Files picker completed ...
Import status displayed outcome=importing ...
Import copy started ... securityScopeGranted=...
Import copy succeeded ...
Import status displayed outcome=success ...
```

If the issue reproduces, the missing or failing line is the diagnosis target:
empty picker result, security-scope denial, copy failure, or final failure
status.

## Pass/Fail Rule

Do not accept a side-loaded build until:

1. Fresh install and upgrade gates pass on at least one Dynamic Island iPhone.
2. Real Files audio import passes on the physical device.
3. Attachment import and persistence pass.
4. Live Activity and App Shortcut routes are tested on device.
5. Crash/log evidence is captured for every failure.
6. Untested items are listed explicitly in the release note.
