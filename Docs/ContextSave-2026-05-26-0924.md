### Dynamic Notch / Beam

Important limitation:

The in-app beam is a fake overlay around/near the real physical Dynamic Island. It can only approximate the island because the system cutout masks/occludes content. Outside the app, the real Dynamic Island must be ActivityKit/WidgetKit.

Recent beam state:

- `DynamicIslandEdgeBeam` is used by `DynamicSlotButton`.
- Frame currently near:
  - width `126`
  - height `36`
  - y offset `13.4`
- Because the bottom edge was still uneven, a separate `DynamicIslandBottomLip` shape was added so the lower lip can be controlled independently from the animated capsule stroke.
- This latest lower-lip approach was built and installed, but needs visual evaluation on the mirrored phone.

Relevant file:

- `MotionReveal/Features/MusicWorkspace/IslandSlotViews.swift`

### Live Activity / Real Dynamic Island

ActivityKit/WidgetKit implementation exists:

- `MotionReveal/Support/NowPlayingActivityAttributes.swift`
- `MotionReveal/Support/NowPlayingLiveActivity.swift`
- `MotionReveal/Features/MusicWorkspace/WorkspaceDynamicIslandCoordinator.swift`
- `MotionRevealLiveActivity/MotionRevealLiveActivityWidget.swift`

Apple docs/user direction:

- Real Dynamic Island outside the app must use ActivityKit/WidgetKit Live Activities.
- Use compact/minimal/expanded regions.
- Avoid long custom widget-side animations.
- Use short state-driven WidgetKit transitions.

Current widget code includes:

- `.contentTransition(.opacity)` for title/play state changes.
- `.contentTransition(.numericText())` for elapsed/duration.
- short `.animation(..., value:)` for track title, project title, progress, and play state.
- Widget-side continuous border animation was removed/reduced in favor of static state accent.

Apple docs links used:

- `https://developer.apple.com/documentation/widgetkit/animating-data-updates-in-widgets-and-live-activities`
- `https://developer.apple.com/documentation/activitykit/displaying-live-data-with-live-activities`
